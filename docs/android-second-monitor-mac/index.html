AnyDisplay/Mac Setup

MAC SETUP

Use your Android
as a second monitor for Mac.

Give a spare Android phone or tablet a place beside your Mac. AnyDisplay creates a real extended display on macOS, with USB or local Wi-Fi carrying the video.

By Yahya Efe Kuruçay · Updated 9 November 2026

What you need

  • A Mac running macOS 14 or later, on Apple silicon or Intel.
  • An Android phone or tablet running Android 8.0 or later.
  • The AnyDisplay Android app and Mac host from the downloads section.
  • For USB: a data-capable cable, Android Platform-Tools on the Mac, and USB debugging enabled on Android.
  • For Wi-Fi: both devices on the same local network.

No display dongle or separate virtual display driver is required on Mac. AnyDisplay creates the display itself. It is an early open-source app, so allow time to check the permissions and your device’s behavior.

1. Install the app on both devices

Open the APK on Android and allow installation from the source you used to download it. Launch AnyDisplay and keep it open while connecting.

On the Mac, unzip the host package and move AnyDisplay.app to Applications. Open it once. The app is ad-hoc signed and not notarized yet; if macOS blocks that first launch, use System Settings → Privacy & Security → Open Anyway for your trusted download.

Look for the overlapping screens icon in the menu bar. AnyDisplay does not open a conventional main window or appear as a regular Dock app.

2. Give the Mac host permission

Use the AnyDisplay menu’s Allow Screen Recording… action for video. Enable Accessibility for touch, pen and keyboard input. Restart the host if macOS asks after a permission change.

These permissions apply to the Mac application. Because the app is ad-hoc signed, an update can require you to enable its permissions again.

3. Connect over USB or Wi-Fi

USB

Install Android SDK Platform-Tools and restart the Mac host so it can find adb. Enable USB debugging in Android’s Developer options, connect the cable, unlock the device and accept its computer authorization prompt. 

adb devices -l

The device state should be device. If it says unauthorized, check the Android screen for the prompt. The Mac menu bar app connects authorized USB devices automatically by default.

If adb lists (no serial number), use AnyDisplay v0.1.1 or newer and keep only one USB Android device attached. That case is supported by explicit USB selection.

Wi-Fi

Join the same local network on both devices. Select the Android device under Wi-Fi in the AnyDisplay menu. On the first pairing, compare the six-digit code and accept it on both screens only if it matches. Wireless sessions use encryption after pairing.

If the device is not discovered, use Connect to Address… and enter the IP shown in the Android app. Check macOS local-network permission and whether the router isolates wireless clients. You do not need to open an internet-facing router port.

4. Arrange the extra screen

Open System Settings → Displays and arrange the new display beside your existing one. Drag a window across the corresponding screen edge. If the tablet looks empty, it may simply be showing a separate desktop with no windows on it yet.

Keep frequently used tools or reference material on Android and your main document on the Mac. Touch and trackpad modes let the Android device send input back; this is more than a video-only preview.

If something does not work

The Mac app seems to disappear
Check the menu bar for the overlapping screens icon.
USB shows no device
Try a data-capable cable, unlock Android and check adb devices -l. Keep the Android app open.
Video is blank
Check Screen Recording permission, restart the host, then check the display arrangement.
Video works but touch does not
Check Accessibility permission for the current AnyDisplay build.

See the full troubleshooting guide for more cases.

What we tested

The maintainer’s Huawei P30 Pro / MacBook Pro setup has been tested over both USB and Wi-Fi. In the v0.1.1 release check, an eight-second USB session sent 149 frames at a configured 2340×1080 resolution using hardware HEVC, with no dropped frames reported. That is a connection smoke test, not a sustained frame-rate benchmark.

Physical stylus testing is still needed. For a different host, use the Windows instructions; to compare software first, read the Android second-monitor app guide.
